## 1. Traceability Architecture & Progression from Milestone 1

In accordance with **SEN381 NQF Level 8 standards** and **Milestone 2 Brief Section 4.2**, the RTM is an evolving engineering instrument, not a static requirements catalog.

In Milestone 1, placeholder columns (`Architecture Ref (M2)`, `Issue/PR Ref (M3)`, etc.) marked forward intent. In Milestone 2, the matrix evolves by fully exposing the structural translation of requirements into:
$$\text{Requirement} \longrightarrow \text{ASR / Quality Driver} \longrightarrow \text{Architecture Layer} \longrightarrow \text{Data / Persistence} \longrightarrow \text{Design Pattern} \longrightarrow \text{Technology (ADR)} \longrightarrow \text{Implementation Artefact} \longrightarrow \text{Verification Status}$$

### Mandatory Column Schema (Milestone 2 Brief §4.2)
1. **Req ID & Current Wording:** Stable identifier and baselined functional/non-functional statement.
2. **Stakeholder & Priority:** Originating stakeholder persona and MoSCoW prioritization.
3. **Acceptance Criteria:** Testable Gherkin acceptance criteria reference.
4. **ASR / Quality-Driver Link:** Direct link to driving architectural quality attribute (`NFR-xxx`).
5. **Architecture / Module / Component:** Clean Architecture layer and component allocation.
6. **Data / Persistence Impact:** Relational schema table, foreign keys, or transaction boundary.
7. **Design / Interface Decision:** Applied GoF design pattern or OpenAPI contract endpoint.
8. **Technology Decision:** Specific runtime, framework, or database technology (`ADR-008`).
9. **Implementation Evidence:** Source file, migration script, or Docker infrastructure path.
10. **Verification Evidence:** Unit test suite, integration test, or container healthcheck.
11. **Lifecycle Status:** `Approved`, `In Development`, `Implemented`, or `Deferred`.
12. **ADR / Change / Risk Reference:** Governing Architecture Decision Record and linked Risk ID.
